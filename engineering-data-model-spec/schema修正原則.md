# schema.prisma文件修正原則

日期：2026-06-08

用途：作為後續修改schema相關內容時的固定遵循原則。

## 修正原則

1. 後續修改只依照已確認的討論清單進行。
2. 未列入清單的段落、版面、欄位，不主動修改。
3. 每次修改前，先列出本次要改的項目清單。
4. 使用者確認清單後，才開始動檔案內容。
5. 規格書內容除欄位定義可保留英文欄位名稱外，其餘文案、標題、說明與示意圖文字都必須使用繁體中文。
6. 內容不得出現亂碼、`??`、問號替代字或無法辨識的文字。
7. 每次產出 schema 規格說明書前，必須檢查文字、表格、程式碼區塊是否正確顯示為繁體中文。
8. 每次修正後，最新版正式執行檔固定維持為 `schema.prisma`，並另存同版號備份檔。
9. schema 版本備份檔命名規則為 `schema-v版本號-日期.prisma`，例如 `schema-v5-2026-06-08.prisma`。
10. 同時需要產出同樣版號的 schema 規格說明書，供初學者與非 IT 背景決策者閱讀。
11. schema 規格說明書命名規則為 `prisma-schema-spec-v版本號-日期.md`，例如 `prisma-schema-spec-v5-2026-06-08.md`。
12. `schema.prisma` 與同版號 schema 規格說明書必須同步，不可只修改其中一份。
13. 不新增超出 MVP 範圍的 model、欄位、index 或 relation，除非使用者明確確認。
14. 每次修改後必須檢查 model 順序、欄位順序、relation、index、default value 與中文是否亂碼。
15. 若專案已有 Prisma 或 Node 環境，修改後應執行 Prisma format 或 validate；若沒有環境，不得擅自下載套件，需先詢問使用者。
16. 版本備份檔只作為留存與比對用途，正式開發與 Prisma 指令仍以 `schema.prisma` 為準。
