## 1. 目標與優先順序

我們要建立一份「台灣信用卡優惠資料庫」，資料分成四種：

1. **銀行**：發卡銀行基本資料。
2. **信用卡**：每張卡的基本資料（卡片本身，不含優惠）。
3. **優惠**：每一筆優惠活動或卡片權益（網站的主要內容）。
4. **優惠 ↔ 卡片對應**：每筆優惠適用哪些卡。

**整理優先順序（由高到低）：**

1. 現金回饋類優惠（目前產品最優先）
2. 該優惠所屬的卡片與銀行基本資料（有優惠才需要建卡）
3. 餐飲、網購、旅遊、交通、分期類優惠

原則：**先有優惠，才回頭補卡片與銀行**。不要為了湊數把沒有優惠可寫的卡也建進來。

## 2. 交付格式

用一份 Google 試算表（或 Excel 檔），內含四個工作表：

| 工作表名稱 | 內容 | 一列代表 |
|---|---|---|
| `banks` | 銀行 | 一家銀行 |
| `cards` | 信用卡 | 一張卡 |
| `offers` | 優惠 | 一筆優惠 |
| `offer_cards` | 優惠與卡片對應 | 一組「優惠 × 卡片」關係 |

規則：

- 欄位名稱照第 5 節的規格，**不要自行增刪欄位或改欄位名稱**；有想補充的資訊寫在「備註」欄。
- 填不出來的欄位**留空白**，不要填「無」「N/A」「不確定」。真的有疑問寫在備註欄。
- 日期一律用 `YYYY-MM-DD` 格式（例：`2026-09-30`）。
- 每個工作表第一列是欄位名稱，從第二列開始填資料。

## 3. 如何搜尋（資料來源規則）

### 3.1 來源優先順序

| 順位 | 來源 | 用途 |
|---|---|---|
| 1 | 銀行官網的**卡片介紹頁** | 卡片基本資料、長期權益 |
| 2 | 銀行官網的**活動/優惠頁**、官方權益手冊 PDF | 期間限定優惠的正式條款 |
| 3 | 銀行官方新聞稿、官方粉專公告 | 輔助確認活動存在與期間 |
| 4 | 部落格、比較網站（如卡優、Money101、PTT） | **只能當線索**，不能當最終依據 |

**鐵則：每一筆優惠的「來源網址」必須是官方頁面（順位 1–3）。** 從部落格看到的優惠，必須回到銀行官網找到對應頁面才能收錄；官網找不到就不收錄，可寫在備註欄回報。

### 3.2 建議搜尋方式

- Google 搜尋模式：`銀行名 + 卡名 + 優惠`、`銀行名 + 卡名 + 權益`、`卡名 + 現金回饋 + 2026`
- 限定官網搜尋：在 Google 加上 `site:` 指定銀行網域，例如：
  - `site:cathaybk.com.tw CUBE 回饋`
  - `site:bank.sinopac.com DAWHO`
- 直接逛銀行官網的「信用卡」→「優惠活動」清單頁，逐筆看。
- 比較網站可以用來**發現**有哪些卡和活動，再逐一回官網查證。

### 3.3 查證要求

- 每筆優惠記下你**實際確認官方頁面的日期**（填入 `查證日期` 欄）。
- 優惠條款以官方頁面當下內容為準；部落格寫的數字與官網不同時，一律以官網為準。
- 活動已結束（結束日在今天之前）原則上不收錄；除非是長期權益改版，收錄新版即可。

## 4. 如何分類

### 4.1 六大分類定義

每筆優惠必須歸入**恰好一個**主分類（填分類代碼）：

| 分類代碼 | 名稱 | 收什麼 | 例子 |
|---|---|---|---|
| `cashback` | 現金回饋 | 以「回饋 %數 / 現金 / 點數折抵」為主要賣點、不限定單一消費場景的優惠 | 一般消費 3% 回饋、新戶前三個月 8% |
| `dining` | 餐飲美食 | 限定餐廳、外送、餐飲通路的優惠 | 週四餐廳 5%、指定套餐折扣 |
| `travel` | 旅遊交通 | 旅遊、機票、訂房、機場服務、海外消費 | 海外消費加碼、機場接送、貴賓室 |
| `online-shopping` | 網購電商 | 限定電商平台或線上消費 | 蝦皮購物節加碼、指定網購 5% |
| `transport` | 交通通勤 | 日常通勤：加油、停車、大眾運輸、悠遊卡自動加值 | 悠遊卡自動加值回饋、加油降價 |
| `installment` | 分期零利率 | 以分期付款、零利率為主要賣點 | 3C 分期 0 利率、旅遊分期 |

### 4.2 分類判斷規則（衝突時依序套用）

一筆優惠常常同時沾到多個分類，依下列順序判斷主分類：

1. **看限定場景，不看回饋形式**：優惠若限定特定消費場景（餐廳、電商、海外…），歸入該場景分類。例：「指定餐廳現金回饋 10%」→ `dining`，不是 `cashback`。
2. **不限場景的回饋** → `cashback`。例：「國內消費不限通路 2%」。
3. **分期優先於場景**：主要賣點是「分期 / 零利率」→ `installment`，即使限定 3C 或旅遊。
4. **海外消費、機場、訂房** → `travel`；**日常通勤（加油、停車、捷運、悠遊卡）** → `transport`。兩者都像時：出遊性質 → `travel`，日常性質 → `transport`。
5. 還是無法判斷：先選你認為最接近的，並在備註欄寫「分類待確認：理由」。

### 4.3 標籤（tags）補充次要分類

主分類只有一個，其他相關面向用 `標籤` 欄補充。規則：

- 用逗號分隔，例如：`現金回饋,新戶,行動支付`
- 建議常用標籤：`新戶`、`行動支付`、`海外`、`加碼`、`需登錄`、`長期權益`、`期間限定`、`指定通路`
- 標籤用詞盡量重複使用上面清單，不要同義詞混用（例如不要一下「新卡友」一下「新戶」）。

### 4.4 「活動」與「長期權益」都算優惠

- **期間限定活動**（有明確起訖日）：正常填 `開始日期`、`結束日期`。
- **長期卡片權益**（卡片本身的固定回饋，無結束日）：日期留空，標籤加 `長期權益`。

## 6. 品質與驗收標準

交付前請自我檢查，工程端會照同樣標準抽驗：

1. **來源**：每筆優惠都有官方來源網址，且點開仍能看到該優惠。
2. **對應完整**：`offers` 每筆都在 `offer_cards` 有至少一列；`offer_cards`、`cards` 用到的代號都找得到對應列。
3. **代號唯一**：銀行代號、卡片代號、優惠代號在各自工作表內不重複。
4. **日期格式**：全部 `YYYY-MM-DD`；結束日期不早於開始日期；已過期活動不收錄。
5. **分類合法**：主分類代碼只出現六個代碼之一；回饋類型只出現五個選項之一。
6. **數字照抄官網**：回饋 %、上限、門檻不自行換算或推估；官網寫法模糊時照抄原文並在備註說明。
7. **留空原則**：查不到的欄位留空，不填猜測值。
8. **術語白話原則**：優惠內容出現銀行自家術語時（會員等級如「大戶Plus」、專案名稱、「指定任務」、自家點數名稱等），必須在「詳細說明」或「條件與限制」欄用白話解釋：該術語是什麼、一般人怎麼達成，並附上官方說明頁連結。檢驗標準：**一個從沒用過這家銀行的人，讀完後不需要另外查資料就能看懂**。寫不出解釋就代表你自己也還沒查清楚，回官網查到為止。

## 7. 常見狀況判斷（FAQ）

**Q1：同一張卡有 5 個優惠，要建幾列？**
`offers` 建 5 列（一列一優惠），`cards` 只建 1 列，`offer_cards` 建 5 列對應。

**Q2：一個活動好幾張卡都適用？**
`offers` 只建 1 列，`offer_cards` 每張適用卡各 1 列。不要為每張卡複製優惠。

**Q3：一個大活動裡面有好幾層回饋（例如一般戶 3%、新戶 8%）？**
若條件與期間相同，寫成 1 筆優惠，在「詳細說明」與「回饋數值」把層級寫清楚。若參加方式、期間或登錄要求不同，拆成多筆。

**Q4：優惠寫「最高 10%」但其實是多項加總？**
「回饋數值」照官網寫（例：最高 10%），「條件與限制」必須拆解各層條件，讓讀者知道 10% 怎麼組成。

**Q5：官網活動頁掛了或改版找不到？**
不收錄，寫在備註回報（附你原本看到的線索來源）。

**Q6：聯名卡的優惠來源是通路（如蝦皮）還是銀行？**
以發卡銀行官方頁為主要來源；通路官方公告可作為輔助來源一併附上。

**Q7：分不清楚是「活動」還是「長期權益」？**
官網有寫活動期間 → 活動（填日期）；寫在卡片權益頁、沒有期限 → 長期權益（日期留空 + 標籤 `長期權益`）。

**Q8：優惠條款裡出現銀行自己的名詞（例如「大戶Plus 加碼 4%」），要怎麼寫？**
不能照抄了事。實際案例：永豐 DAWHO 卡「大戶Plus 等級加碼 4%、大戶等級加碼 2.5%」——「大戶Plus」「大戶」是永豐 DAWHO 數位帳戶的會員分級，讀者不會知道。正確寫法是在詳細說明補上：等級怎麼分（大戶＝當月平均財富 30 萬元以上；大戶Plus＝100 萬元以上＋當月完成台股交易或換匯任務）、幾時生效（次月），並附官方分級制度連結。「指定任務」也一樣，必須寫出任務具體是哪幾件事（例如：綁定帳戶自動扣繳＋改用電子帳單，兩項同時達成）。見第 6 節第 8 條「術語白話原則」。

## 8. 建議工作流程

1. 選一家銀行，開官網信用卡優惠清單頁。
2. 先掃一輪，挑出**現金回饋類**優惠優先整理。
3. 每筆優惠：確認官方頁 → 填 `offers` 一列 → 確認適用卡片 → `cards`／`banks` 缺的補上 → 填 `offer_cards` 對應。
4. 一家銀行整理完，跑一次第 6 節的自我檢查。
5. 交付時註明：涵蓋哪些銀行、整理期間、已知未收錄項目（及原因）。
