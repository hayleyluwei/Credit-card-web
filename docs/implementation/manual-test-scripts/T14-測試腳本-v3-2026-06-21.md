# T14 測試腳本 v3 - 後台優惠維護 UX 修正版

版本：v3  
日期：2026-06-21  
目的：接續 T14 v2，驗證後台優惠維護的 4 筆修正：公開頁另開、穩定欄位提醒、優惠表單欄位指引、發布驗證錯誤處理。

## 前置條件

- 本機服務已啟動：

http://localhost:3000/

- 後台登入：

http://localhost:3000/admin/login

- 帳號：`admin@example.com`
- 密碼：`replace-with-a-local-admin-password`

## 1. 後台優惠管理：查看公開頁應另開

開啟：

http://localhost:3000/admin/offers

操作：

- 找任一筆已發布優惠。
- 點「查看公開頁（另開新分頁）」。

預期：

- 公開頁應在新分頁開啟。
- 原本的後台優惠管理頁仍留在原分頁。
- 頁面上方應提示「查看公開頁」會另開新分頁。

## 2. 銀行與信用卡管理：穩定欄位提醒

開啟：

http://localhost:3000/admin/cards

預期：

- 看到「Slug 是公開網址識別，建立後預設不要修改」。
- 看到「SEO 欄位不會因優惠更新自動覆蓋」。
- 卡面圖片 URL 說明應講清楚會顯示在信用卡詳情頁、銀行詳情頁、優惠詳情頁。

開啟：

http://localhost:3000/admin/banks

預期：

- 看到「Slug 是公開網址識別，建立後預設不要修改」。
- 看到「SEO 欄位不會因優惠更新自動覆蓋」。
- 理解更新優惠時不應順手改銀行 slug / SEO。

## 3. 新增優惠：欄位填寫指引與前台對應圖

開啟：

http://localhost:3000/admin/offers/new

預期：

- 看到「前台欄位對應圖」。
- 圖中至少有：
  - 優惠卡片 / 搜尋結果
  - 優惠詳情頁
  - SEO / 維護
- 表單欄位有反灰提示，例如：
  - 列表摘要：`每週四國內餐廳單筆滿 NT$2,000，享 5% 小樹點優惠券`
  - 適合對象：`常在國內餐廳消費、持有 CUBE 卡的使用者`
  - 標籤：`餐飲,CUBE,小樹點,週四`
  - 亮點 1：`加碼 5% 優惠券`
  - 亮點 2：`每張優惠券上限 100 點小樹點`
  - 詳細說明：`活動期間、適用通路、消費門檻、回饋方式、上限與注意事項`
- 表單上方應說明發布前會檢查：
  - 官方來源連結
  - 回饋方式或回饋內容
  - 至少一張適用信用卡

## 4. 發布缺欄位：不可出現 Runtime Error

開啟：

http://localhost:3000/admin/offers/new

操作：

- 只填「優惠標題」，例如：`發布驗證測試優惠`
- 不填官方來源連結。
- 不填回饋方式與回饋內容。
- 不勾選適用信用卡。
- 點「儲存並發布」。

預期：

- 不應出現 `Unhandled Runtime Error`。
- 不應出現 Next.js 紅色錯誤 overlay。
- 應留在表單頁。
- 頁面上方應顯示：
  - `發布前請填寫官方來源連結`
  - `發布前請填寫回饋方式或回饋內容`
  - `發布前請至少勾選一張適用信用卡`
- 該優惠不應被公開發布。

## 5. 儲存草稿仍可保留不完整資料

開啟：

http://localhost:3000/admin/offers/new

操作：

- 只填「優惠標題」。
- 點「儲存草稿」。

預期：

- 可以儲存為草稿。
- 不需要立刻填完整發布欄位。
- 進入編輯頁後狀態應仍是草稿。
