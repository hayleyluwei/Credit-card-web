# T14 測試腳本 v4 - 待修正 1-10 驗證

版本：v4  
日期：2026-06-22  
目的：驗證信用卡與優惠後台儲存回饋、Slug 修改提醒、前台摘要/亮點顯示、分類頁移除技術欄位。

## 前置條件

本機服務：

http://localhost:3000/

後台登入：

http://localhost:3000/admin/login

帳號：`admin@example.com`  
密碼：`replace-with-a-local-admin-password`

## 1. 編輯信用卡儲存成功要有回饋

開啟：

http://localhost:3000/admin/cards

再點任一張信用卡的「編輯」，例如：

http://localhost:3000/admin/cards/51

操作：

- 在「描述」欄位補一段文字，例如：`無上限測試`
- 不修改 Slug。
- 點「儲存草稿 / 更新」。

預期：

- 頁面不應完全沒反應。
- 應看到「信用卡已成功儲存」或儲存中的按鈕狀態。
- 應看到：
  - 回信用卡管理列表
  - 回後台首頁
  - 查看公開頁（另開新分頁）

## 2. 信用卡 Slug 修改要跳提醒

開啟：

http://localhost:3000/admin/cards/51

操作：

- 修改 Slug，例如把 `dawho-cashback-card` 改成 `dawho-cashback-card1`。

預期：

- 修改 Slug 時應跳出提醒。
- 提醒應說明 Slug 會影響公開網址、舊網址可能失效。
- 取消提醒時，Slug 應回到原值。
- 確認提醒後，才允許本次修改。

## 3. 信用卡編輯頁可還原本次修改

開啟：

http://localhost:3000/admin/cards/51

操作：

- 任意修改描述或摘要。
- 點「還原本次修改」。

預期：

- 欄位回到進入頁面時的值。
- 此功能是 MVP 簡易還原，不是跨次版本紀錄。

## 4. 編輯優惠儲存後要有返回選項

開啟：

http://localhost:3000/admin/offers

再點任一優惠的「編輯」，例如：

http://localhost:3000/admin/offers/131

操作：

- 修改「列表摘要」。
- 點「儲存草稿」。

預期：

- 頁面應顯示儲存成功訊息。
- 應看到：
  - 回優惠管理列表
  - 回後台首頁
  - 查看公開頁（另開新分頁，若有公開頁）

## 5. 新增優惠儲存後也要有返回選項

開啟：

http://localhost:3000/admin/offers/new

操作：

- 填「優惠標題」。
- 點「儲存草稿」。

預期：

- 草稿可建立。
- 進入編輯頁後，表單操作區應有：
  - 回優惠管理列表
  - 回後台首頁

## 6. 優惠 Slug 修改要跳提醒

開啟：

http://localhost:3000/admin/offers/131

操作：

- 修改 Slug。

預期：

- 修改 Slug 時應跳出提醒。
- 提醒應說明 Slug 會影響公開網址。
- 取消時恢復原值，確認後才允許修改。

## 7. 優惠列表摘要要顯示在前台優惠卡片

開啟後台：

http://localhost:3000/admin/offers/131

操作：

- 將「列表摘要」改成容易辨識的文字，例如：`指定 3C 通路分期零利率測試優惠123。`
- 點「儲存草稿」或「儲存並發布」。

再開啟前台搜尋頁：

http://localhost:3000/search

也可開啟分類頁：

http://localhost:3000/categories/installment

預期：

- 對應優惠卡片標題下方應顯示你修改的列表摘要。
- 列表摘要不應被亮點 1 / 亮點 2 蓋掉。

## 8. 分類前台不應顯示後台技術欄位

開啟：

http://localhost:3000/categories/cashback

預期：

- 不應看到「分類 Slug」。
- 不應看到「SEO 標題」。
- 右側只應顯示一般使用者看得懂的分類說明、挑選提示或常見問題。

## 9. 優惠亮點要能在前台詳情頁找到

開啟後台：

http://localhost:3000/admin/offers/131

確認欄位：

- 亮點 1
- 亮點 2

再開啟對應前台優惠頁，例如：

http://localhost:3000/offers/cube-3c-installment

預期：

- 前台優惠詳情頁應有「優惠亮點」區塊。
- 亮點 1 / 亮點 2 有值時，應顯示在「優惠亮點」區塊。

## 10. 發布缺欄位仍不可出現 Runtime Error

開啟：

http://localhost:3000/admin/offers/new

操作：

- 只填「優惠標題」。
- 不填來源連結。
- 不填回饋方式與回饋內容。
- 不勾選適用信用卡。
- 點「儲存並發布」。

預期：

- 不應出現 `Unhandled Runtime Error`。
- 應留在表單頁。
- 應顯示中文錯誤訊息，提示缺少來源連結、回饋資訊、適用信用卡。
