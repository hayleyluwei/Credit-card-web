## 測試 1：Sitemap 生成與格式

### 步驟

1. 在瀏覽器中開啟 `http://localhost:3000/sitemap.xml`
2. 檢查 XML 內容是否包含以下項目：
   - 根元素：`<urlset>`
   - 首頁：`<loc>http://localhost:3000</loc>`
   - 至少 1 個分類：`/categories/[slug]` 形式
   - 至少 1 個銀行：`/banks/[slug]` 形式
   - 至少 1 個卡片：`/cards/[slug]` 形式
   - 至少 1 個優惠：`/offers/[slug]` 形式（僅 `isPublished=true`）

3. 檢查每個 `<url>` 區塊包含：
   - `<loc>` - 完整 URL
   - `<lastmod>` - 修改日期 (YYYY-MM-DD 格式)
   - `<priority>` - 優先權 (0.0-1.0)
   - `<changefreq>` - 更新頻率 (daily/weekly)

### 預期結果

✅ Sitemap 是有效的 XML 格式  
✅ 所有公開頁面都列在 sitemap 中  
✅ 未發布的優惠不出現在 sitemap 中  
✅ 優先權正確（首頁 > 分類 > 銀行/卡片 > 優惠）

### 失敗時截圖/報告

- 如果 sitemap 是空的或無效，擷取整個頁面內容
- 如果遺漏某些頁面，列出缺漏的 slug

## 測試 2：Robots.txt 生成與正確性

### 步驟

1. 在瀏覽器中開啟 `http://localhost:3000/robots.txt`
2. 檢查內容是否包含：
   - `User-agent: *` - 允許所有爬蟲
   - `Allow: /` - 允許根路徑
   - `Disallow: /admin` - 禁止爬蟲訪問管理員區域
   - `Disallow: /api` - 禁止爬蟲訪問 API
   - `Sitemap:` - 指向 sitemap.xml 的完整 URL

### 預期結果

✅ Robots.txt 內容正確  
✅ 管理員和 API 路由被禁止  
✅ Sitemap URL 正確指向 `/sitemap.xml`

### 失敗時截圖/報告

- 擷取整個 robots.txt 內容

## 測試 3：首頁 Metadata 和 Organization JSON-LD

### 步驟

1. 開啟 `http://localhost:3000`
2. 開啟瀏覽器開發者工具 > Inspect 頁籤
3. 在源代碼中搜尋 `type="application/ld+json"`（Ctrl+F）
4. 找到 `@context: "https://schema.org"` 的 JSON-LD 區塊
5. 檢查內容：

   **expected structure:**
   ```json
   {
     "@context": "https://schema.org",
     "@type": "Organization",
     "name": "信用卡優惠查詢網站",
     "url": "http://localhost:3000",
     "description": "...",
     ...
   }
   ```

### 預期結果

✅ JSON-LD 存在並包含 `@context` 和 `@type`  
✅ Organization 包含 name、url、description  
✅ JSON 格式有效（無語法錯誤）

### 失敗時截圖/報告

- 擷取頁面源代碼中的 `<script type="application/ld+json">` 區塊

## 測試 4：分類詳情頁 Metadata 與 Canonical URL

### 步驟

1. 開啟任意分類詳情頁，例如 `http://localhost:3000/categories/travel`
2. 開啟瀏覽器開發者工具 > Head section
3. 檢查 `<head>` 中是否包含：
   - `<title>` - 應包含分類名稱和「｜信用卡優惠查詢網站」
   - `<meta name="description">` - 包含分類描述或預設文字
   - `<link rel="canonical">` - href 應為 `http://localhost:3000/categories/[slug]`

4. 檢查 JSON-LD：
   - 搜尋 `type="application/ld+json"` 區塊
   - 應該看到 WebPage 類型的 JSON-LD

### 預期結果

✅ Title 和 description 都正確設定  
✅ Canonical URL 指向正確的分類頁  
✅ JSON-LD 存在（WebPage 類型）  
✅ 如果分類有 FAQ，應該看到 FAQPage JSON-LD

### 失敗時截圖/報告

- 擷取 Head section 中缺漏的元素

---

## 測試 5：優惠詳情頁 Metadata 與 Article JSON-LD

### 步驟

1. 開啟任意已發布優惠詳情頁，例如 `http://localhost:3000/offers/[slug]`
2. 開啟瀏覽器開發者工具 > Head section
3. 檢查 `<head>` 中：
   - `<title>` - 應包含優惠標題
   - `<meta name="description">` - 優惠摘要或系統生成的描述
   - `<link rel="canonical">` - `http://localhost:3000/offers/[slug]`

4. 檢查 JSON-LD：
   - 應該看到 Article 類型的 JSON-LD
   - 應包含 `datePublished` 和 `dateModified`
   - 如果優惠有 FAQ，應該額外看到 FAQPage JSON-LD

### 預期結果

✅ Title 和 description 正確  
✅ Canonical URL 指向優惠頁  
✅ Article JSON-LD 存在並包含日期  
✅ 如果有 FAQ 資料，FAQPage JSON-LD 也存在

### 失敗時截圖/報告

- 擷取 JSON-LD 區塊或缺漏的元素
