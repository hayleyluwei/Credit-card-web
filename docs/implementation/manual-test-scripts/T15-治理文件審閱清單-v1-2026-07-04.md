# T15 治理文件審閱清單

版本：v1

任務：T15 AI 開發治理導入  
用途：純文件／治理任務人工驗收，不需要啟動網站或修改資料

## 前置條件

- 使用 UTF-8 閱讀 Markdown 與 JSON。
- 不需要執行 dev server、build、seed、db push 或 migration。
- 不需要 commit、push 或部署。

## 1. 新對話入口

- [ ] 開啟 `AGENTS.md`。
- [ ] 確認內容會引導 AI 讀取 `AI_WORKFLOW_AI協作流程.md`、`CURRENT_STATE_目前專案狀態.md`、目前任務卡與最近 Summary。
- [ ] 確認規則優先序包含平台安全、使用者指令、專門流程、已核准任務卡及 AI_WORKFLOW。

通過標準：新 AI 不需重讀所有歷史文件，也能找到目前狀態與正式規則。

## 2. Scope 與三層權限

- [ ] 確認 Scope 未核准時只能分析、規劃及更新治理事實。
- [ ] 確認 Scope 核准後可在範圍內連續實作，不逐檔詢問。
- [ ] 確認 schema、migration、共用資料、正式環境、push、部署及破壞性 Git 操作必須先確認。
- [ ] 確認任務卡會記錄 Scope 版本與核准證據。

通過標準：低風險工作不反覆詢問，高風險操作不能被模糊授權繞過。

## 3. 驗證白名單

- [ ] 開啟 `docs/sop/AI_VERIFICATION_POLICY_自動驗證政策.json`。
- [ ] 確認 `defaultClassification` 是 `unclassified`。
- [ ] 確認 `policyChangeRequiresUserApproval` 是 `true`。
- [ ] 確認初始 `commands` 是空陣列，沒有 AI 自行核准的測試。
- [ ] 確認 `AI_WORKFLOW` 與驗證 SOP 都規定 fingerprint 或核准失效時不可自動執行。

通過標準：只有使用者核准且分類有效的測試能進入 Tier 1。

## 4. Worktree 寫入鎖

- [ ] 確認 `.gitignore` 包含 `.ai-worktree-lock.json`。
- [ ] 確認 lock 使用 `FileMode.CreateNew` 或等效原子操作，不可覆蓋。
- [ ] 確認其他 session 持有 lock 時不能寫入。
- [ ] 確認殘留或過期 lock 不能由 AI 自行刪除。

通過標準：多 AI 寫入衝突能在第一次修改前被攔下，而不是只靠事後 Git status。

## 5. Dev server 與本機驗證

- [ ] 確認本機 SOP 使用 `Get-NetTCPConnection` 或 `netstat -ano` 檢查 port。
- [ ] 確認會依 PID 核對 Node／Next 與專案目錄。
- [ ] 確認無法判斷程序所有者時，視為存在共用 dev server。
- [ ] 確認 AI 不得自行停止程序、刪除 `.next` 或執行共用 build。
- [ ] 確認 `db:seed`、`db:push` 及共用資料寫入測試不能自動執行。

通過標準：已知的 `.next` stale chunk 與本機資料重設風險都有具體防線。

## 6. 任務與部署狀態

- [ ] 確認任務狀態與部署狀態分開。
- [ ] 確認「完成」不等於「已部署」。
- [ ] 確認 Preview／Production 的已部署與已驗證分開記錄。
- [ ] 確認無法查證時使用 `未知`。

通過標準：AI 不會把程式完成、人工驗收和正式部署混為一談。

## 7. 文件責任與歷史

- [ ] 確認 `CURRENT_STATE_目前專案狀態.md` 使用固定檔名持續更新。

- [ ] 確認規格書與 schema 專門流程仍保留原位且優先。

通過標準：目前狀態、任務索引、Summary、Roadmap 與正式規格不互相取代。

## 8. 繁體中文與機密

- [ ] 確認所有新治理文件使用繁體中文標題與中文說明。
- [ ] 確認文件沒有亂碼或 Unicode replacement character。
