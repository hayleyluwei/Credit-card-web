# T07 Manual Test Script - Search Listing Sorting

日期：2026-06-15  
版本：v1  
任務：Search Listing Sorting

## 前置條件

- 已完成 T06 優惠詳情頁
- 已執行 `npm run dev`，並能成功訪問 `http://localhost:3000`
- 已執行 `npm run db:seed`

## 測試步驟

### 步驟 1：搜尋頁基本顯示

1. 前往 `http://localhost:3000/search`
2. 檢查搜尋輸入欄、搜尋說明區是否顯示。
3. 不輸入任何關鍵字，確認頁面顯示「輸入關鍵字開始搜尋」訊息。

**預期結果：**
- 搜尋頁面正常加載，無任何錯誤。

### 步驟 2：搜尋優惠名稱

1. 在搜尋輸入欄輸入一個已知優惠的部分名稱，例如 `cashback`。
2. 按 Enter 或等待頁面自動搜尋。
3. 檢查結果區是否列出相關優惠卡片。

**預期結果：**
- 顯示「找到 X 個結果」
- 相關優惠以優惠卡片格式顯示
- 排序依據優先級：優惠名稱 > 標籤 > 分類 > 摘要 > 描述

### 步驟 3：搜尋銀行或分類名稱

1. 輸入一個銀行名稱的部分文字，例如 `mega` 或分類名稱如 `cashback`。
2. 檢查是否顯示該銀行或分類對應的優惠結果。

**預期結果：**
- 銀行/分類名稱符合時，顯示相關優惠。

### 步驟 4：空結果狀態

1. 輸入一個不存在的關鍵字，例如 `xyz123456`。
2. 檢查頁面是否顯示「未找到與『xyz123456』相關的優惠。」

**預期結果：**
- 空結果狀態清晰，提示用戶修改搜尋條件。

### 步驟 5：多關鍵字搜尋

1. 輸入多個關鍵字，例如 `cashback 回饋`。
2. 檢查結果是否包含同時符合任一關鍵字的優惠。

**預期結果：**
- 支援多個空格分隔的關鍵字。

## 驗收清單

- [ ] 搜尋頁面 `/search` 正常顯示
- [ ] 無關鍵字時顯示「輸入關鍵字開始搜尋」訊息
- [ ] 搜尋優惠名稱返回相關結果
- [ ] 搜尋分類名稱返回相關優惠
- [ ] 空結果狀態清晰
- [ ] 優惠卡片顯示正確（使用 T05/T06 的 OfferCard 元件）
- [ ] 排序依據優先級正確（名稱 > 標籤 > 分類 > 摘要 > 描述）

## 問題排查

### 搜尋無任何結果

- 確認 `Offer.isPublished` 為 true
- 確認搜尋關鍵字在優惠、銀行、卡片或分類名稱中
- 確認 `/api/search` 端點返回資料（打開瀏覽器開發者工具的 Network 標籤查看）

### 排序顯示不對

- 確認 `performSearch` 函式的排序邏輯已正確應用
- 確認 `offer.isFeatured`、`offer.recommendScore`、`offer.sortOrder` 在 seed 資料中設置正確
