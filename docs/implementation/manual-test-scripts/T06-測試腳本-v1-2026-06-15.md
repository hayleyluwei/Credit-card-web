# T06 Manual Test Script - Public Detail Pages

日期：2026-06-15  
版本：v1  
任務：Public Detail Pages

## 前置條件

- 已完成 T05 公共前端骨架
- 已執行 `npm run dev`，並能成功訪問 `http://localhost:3000`
- 已執行 `npm run db:seed`

## 測試步驟

### 步驟 1：銀行頁面測試

1. 前往一個已存在的銀行 slug，例如 `http://localhost:3000/banks/mega-bank`（請依 seed 資料實際 slug 調整）。
2. 檢查銀行名稱、描述、Logo（若有）是否顯示。
3. 確認頁面列出該銀行的啟用卡片。
4. 點選卡片連結後，應進入卡片詳情頁。
5. 確認該銀行相關優惠區顯示已發布優惠。

**預期結果：**
- 銀行資訊與卡片列表正常呈現。
- 相關優惠列表可見，優惠卡片能正確點擊。

### 步驟 2：卡片頁面測試

1. 前往一個已存在的卡片 slug，例如 `http://localhost:3000/cards/visa-platinum`。
2. 檢查卡片名稱、銀行名稱、目標客群、卡片說明是否顯示。
3. 確認右側資訊欄顯示 SEO 標題與啟用狀態。
4. 檢查相關優惠區是否顯示對應的公開優惠。
5. 點選優惠進入優惠詳情頁。

**預期結果：**
- 卡片詳情頁正常顯示，且相關優惠可被瀏覽。

### 步驟 3：優惠詳情頁測試

1. 前往一個已存在的優惠 slug，例如 `http://localhost:3000/offers/cashback-special`。
2. 檢查優惠標題、摘要、狀態標籤是否顯示。
3. 確認優惠內容包含回饋方式、回饋內容、使用門檻、優惠條件、優惠期間、最後驗證與來源連結。
4. 檢查適用卡片區是否列出與該優惠關聯的卡片。

**預期結果：**
- 優惠詳情頁完整顯示所有公開欄位。
- 適用卡片可正確跳轉到卡片詳情頁。

### 步驟 4：404 與無效 slug 測試

1. 前往一個不存在的銀行 slug，例如 `http://localhost:3000/banks/not-a-bank`。
2. 前往一個不存在的卡片 slug，例如 `http://localhost:3000/cards/not-a-card`。
3. 前往一個不存在的優惠 slug，例如 `http://localhost:3000/offers/not-an-offer`。

**預期結果：**
- 所有不存在 slug 應呈現 404 或 Next.js 的 not-found 處理頁面。

## 驗收清單

- [ ] 銀行頁面 `/banks/[slug]` 正常顯示銀行資訊與卡片列表
- [ ] 卡片頁面 `/cards/[slug]` 顯示卡片資訊與關聯優惠
- [ ] 優惠頁面 `/offers/[slug]` 顯示優惠完整內容
- [ ] 過期優惠標記與來源連結顯示正確
- [ ] 不存在 slug 返回 404

## 問題排查

### 銀行卡片無法顯示

- 確認 `Bank.isActive` 與 `Card.isActive` 都為 true
- 確認 seed 資料中 `Card.bankId` 對應正確銀行

### 優惠詳情顯示 404

- 確認該優惠 `isPublished` 為 true
- 確認該優惠 `showExpiredOffers` 設定是否允許展示過期優惠
