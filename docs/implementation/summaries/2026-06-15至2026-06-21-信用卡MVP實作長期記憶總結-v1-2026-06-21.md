# 信用卡 MVP 實作長期記憶總結 v1

涵蓋期間：2026-06-15 至 2026-06-21  
建立日期：2026-06-21  
用途：濃縮 T01-T13 與早期 UX follow-up 的可延續記憶，讓後續工作不必重新讀大量舊 summary。

## 專案基本狀態

- 專案名稱：信用卡優惠查詢網站 MVP。
- 主要專案資料夾：`C:\Users\user\Documents\Credit card web project`
- 技術棧：Next.js App Router、TypeScript、Tailwind CSS、Prisma、SQLite、NextAuth。
- 本機服務預設：`http://localhost:3000`
- 常用指令：
  - 啟動：`npm.cmd run dev -- --hostname 127.0.0.1 --port 3000`
  - 重建 seed：`npm.cmd run db:seed`
  - lint：`npm.cmd run lint`
  - build：`npm.cmd run build`
- 注意：`npm.cmd run db:seed` 會清空並重建本機 `dev.db`，使用者在後台手動改的資料會被重設。
- 若 build 後 dev server 出現 stale chunk / cannot find module 類錯誤，處理方式是停止 3000、清 `.next`、重新啟動 dev server。

## MVP 邊界

- Prisma schema v2 是資料模型來源。
- 實作使用 camelCase 欄位名稱，對應產品規格概念欄位。
- 不新增 MVP-excluded models：
  - `AuditLog`
  - `FaqItem`
  - `Tag`
  - `OfferTag`
  - `Redirect`
  - `CrawlSource`
  - `ImportJob`
- 不新增 `canonicalUrl` DB 欄位。
- 不新增 `SiteSetting.homepageFaqJson`。
- 圖片只存 URL/path，不存 binary。
- 前台預設只顯示 `isPublished = true` 的優惠。
- 過期優惠顯示依 `SiteSetting.showExpiredOffers` 控制。

## 核心資料模型記憶

- `SiteSetting`
  - 網站名稱、SEO fallback、首頁精選數量、分類頁筆數、是否顯示過期優惠。
- `AdminUser`
  - 單一後台管理者 MVP。
  - 使用 bcrypt hash 密碼。
- `Bank`
  - 銀行資料、slug、logo、官網、SEO、啟用狀態。
- `Card`
  - 信用卡資料、銀行關聯、slug、卡面圖片 URL、摘要、說明、目標客群、SEO、啟用狀態。
- `Category`
  - 優惠分類、slug、icon、描述、SEO、FAQ JSON、排序、啟用狀態。
- `Offer`
  - 優惠主體：標題、slug、摘要、亮點、詳細說明、期間、回饋、條件、來源、標籤、SEO、FAQ、精選、排序、發布狀態。
- `OfferCard`
  - 優惠與信用卡的 many-to-many 關聯。
  - 不要只用銀行推論適用卡片，應精準連到實際卡片。

## Domain Helper 長期記憶

主要檔案：

- `src/lib/domain-validation.ts`
- `src/lib/domain-parsing.ts`
- `src/lib/domain-offers.ts`
- `src/lib/domain-search.ts`
- `src/lib/domain-seo.ts`

重要規則：

- `validateFaqJson`
  - FAQ JSON 必須是陣列。
  - 每個 item 要有非空 `question` 與 `answer`。
  - 空值可通過，代表沒有 FAQ。
- `validateOfferPublish`
  - 發布優惠必填：
    - title
    - slug
    - categoryId
    - summaryPreview
    - sourceUrl
    - rewardType 或 rewardValue 至少一個
    - 至少一張適用信用卡
- `generateSlug`
  - 用於依標題產生 slug。
  - slug 是公開 URL 識別，建立後預設不要隨意修改。
- `parseTags`
  - 逗號分隔、trim、移除空值。
- `resolveSummaryPreview`
  - 摘要優先順序：
    1. manualSummary
    2. highlight1 + highlight2
    3. summaryPreview / summary
    4. title fallback
- `getPublicOffers`
  - 過濾已發布與過期顯示規則。
- `sortOffers`
  - 排序優先：精選、推薦分數、排序值、更新時間。
- `domain-seo`
  - canonical 由 base URL + path 產生，不進 DB。
  - sitemap 包含首頁、分類、銀行、信用卡、已發布優惠。
  - robots 允許公開頁、阻擋 admin/api。
  - JSON-LD 包含 Organization、WebPage、Article、FAQPage、Breadcrumb 類型。

## 後台資料維護規則

更新信用卡優惠時，預設只更新：

- `Offer` 的活動內容、期間、回饋、限制、來源、SEO/FAQ、發布狀態、排序。
- `OfferCard` 的適用信用卡關聯。

預設不要修改：

- `Bank.slug`
- `Bank.seoTitle`
- `Bank.seoDescription`
- `Card.slug`
- `Card.seoTitle`
- `Card.seoDescription`
- 銀行名稱 / 卡片名稱，除非官方名稱真的改變且使用者確認。

原因：

- 銀行與卡片是相對穩定的資料。
- 單一優惠更新不應意外改變銀行/卡片公開網址或 SEO。
- 後台已加提醒，但目前 bank/card edit 頁仍允許 slug 編輯；未來可考慮加確認或鎖定。

真實資料觀察：

- 現有 schema 可先承載真實卡與優惠，不必立即改 schema。
- `conditions` 可能變長，因為會混合資格、任務、上限、排除項、期限。
- `rewardCap` 可放簡單上限，但多等級/多帳單週期上限會變密。
- `Offer` 同時承載活動與常態權益，目前可用，但未來 UI 可能需要更清楚區分。
- `Card.sourceUrl` 目前不是 schema 欄位；卡片官方來源若變重要，需另開 schema/spec 討論。

## 真實優惠內容轉換規則

已建立專案限定 skill：

- `.codex/skills/credit-card-offer-extractor/SKILL.md`
- `.codex/skills/credit-card-offer-extractor/references/content-patterns.md`

使用時機：

- 將官方信用卡優惠頁轉成 seed、Offer 欄位、前台內容或 smoke/manual 測試期待。

核心原則：

- 不要只寫「用於測試」「依官方活動」「相關優惠」。
- 內容要回答：
  - 什麼期間？
  - 哪張卡？
  - 哪個通路/店家？
  - 要做什麼？
  - 門檻多少？
  - 拿到什麼？
  - 上限/費用/不可併用是什麼？
  - 哪些條件會讓使用者不符合？

代表案例：

- CUBE 餐飲系列活動
  - 每週四持 CUBE 信用卡國內餐廳消費單筆滿 NT$2,000。
  - 可獲加碼 5% 優惠券。
  - 每張優惠券回饋上限 100 點小樹點。
  - 單月餐廳消費累積滿 NT$20,000 可再依官方規則取得指定餐廳 10% 小樹點優惠券。
  - 需確認是否登錄/領券、餐廳是否在官方認列範圍。
- DAWHO 大戶屋套餐 9 折
  - 活動期間：2026/5/15-2026/7/14。
  - 至大戶屋餐廳點「永豐DAWHO幣倍套餐」。
  - 結帳出示永豐DAWHO信用卡/幣倍卡。
  - 專屬套餐優惠價 $460/份，原價 $510。
  - 另須支付原價 10% 服務費。
  - 不得與其他店內優惠併用。
  - 套餐內容需完整列出。

## 已知注意事項

- 本環境使用 PowerShell 時，直接讀含中文的檔案可能在 terminal 顯示亂碼；實際檔案與瀏覽器頁面可能仍是 UTF-8 正常。
- 編輯中文檔案時，應用 `apply_patch`，避免 PowerShell here-string 造成 mojibake。
- `npm` 在 Windows 可能遇到 execution policy，使用 `npm.cmd`。
- 若要寫入 `.next`、啟動/停止 dev server、寫 SQLite `dev.db`，常需要 escalation。
- 不要在使用者正在測試且想保留資料時跑 `npm.cmd run db:seed`。
