## 背景

2026-07-27 使用者提出疑慮：之後要幫平台上的信用卡補上真實卡面圖片時，如果直接從銀行官網抓取卡面照片或去背圖直接使用，是否比較好改一下風格再呈現？

查證現況（2026-07-27）：資料庫目前 **11 張卡，0 張設有 `imageUrl`**，前台一律以卡片名稱首字的色塊頭像（`CardImage` 元件的 fallback）呈現，尚未實際使用過任何真實卡面圖片。因此這是一個**預防性**任務——趁還沒有人蒐集/上傳任何卡面圖片之前，先定規則，而不是問題已經發生。

這個顧慮的核心是：銀行卡面設計與行內 Logo 通常屬於銀行的商標／著作權資產，直接抓取官網圖片重製在第三方網站上，可能有著作權或商標權疑慮。這與本專案既有的內容政策一致——規格書已明文規定文字內容「KOL 文章只參考資訊架構與選題，不得抄錄原文，數字回官方來源查證後改寫」；卡面圖片若直接沿用官方素材，等於是同一類風險換了一種媒材。

相關文件：
- `src/components/CardImage.tsx`（現有卡面圖片元件，含無圖時的色塊頭像 fallback）
- `prisma/schema.prisma` 的 `Card.imageUrl`／`imageAlt` 欄位
- `docs/data-collection/DATA_COLLECTION_SPEC_信用卡優惠資料蒐集與分類規格書-v3-2026-07-27.md`（內容來源與著作權原則章節）

## 已確認決策

- 使用者 2026-07-27 傾向：**不直接沿用銀行官網的卡面照片**，希望之後如果要放卡面圖片，先經過風格轉換再呈現。
- **使用者 2026-07-27 選定方向 (b)：委託簡化插畫**（保留卡片配色與大致版型意象，不逐像素重製官方設計）。
- **待解決的執行方式問題（使用者 2026-07-27 提出）**：使用者擔心無論是 Claude 或 Codex，AI 圖像生成工具都無法保證多張卡片之間風格一致——這是真實存在的技術限制，AI 逐次生成的插畫在線條、配色飽和度、視角上本來就會有變異，不是能單純靠「講清楚一點」解決的問題。
- **AI 提出的替代執行方案（待使用者確認是否採用）**：與其請 AI「畫」每張卡的插畫（每次生成結果不可控），改用**參數化 SVG 樣板系統**——由工程端設計一份可重複使用的卡片視覺樣板（簡化幾何造型、依銀行/卡片等級決定主色、依發卡組織顯示對應簡易圖示等），每張卡的視覺由同一份樣板套入資料產生，而非個別生成的獨立創作。優點：風格保證一致（本質是同一段程式碼），新卡加入時自動套用不需要重新設計，且不重製官方卡面設計、著作權風險低。這改變了「委託插畫」的執行方式定義：從「請人／AI 逐張手繪」變成「設計一套規則、寫程式產生」。
  - **原型已完成（2026-07-27）**：AI 用 4 張真實卡片資料（`esun-unicard`／`hsbc-travelone-infinite`／`ctbc-line-pay-card`／`taishin-richart-card`，涵蓋乾淨值、英文 tier、複合雜亂字串、全 null 四種情況）產生參數化 SVG 卡面，發布為 Artifact 供使用者檢視。規則：底色依銀行 slug 雜湊固定指派（8 色深色盤）、發卡組織標籤從 `cardNetwork` 關鍵字比對抽取（抽不到不顯示原始字串）、金色 tier 裝飾線依 `cardLevel` 關鍵字比對顯示。**原型未觸及任何正式程式碼**（`CardImage.tsx` 未修改），純獨立展示頁。

  - **2026-07-28～29 回饋與迭代過程**（新增）：
    1. 使用者指出中國信託 Dynasty Flyer 系列同一張卡的不同 tier（Priority／Infinite Business／Signature Business）顏色差異很大，質疑「依銀行代號雜湊、同銀行永遠同色」的規則無法呈現這種同系列分色。AI 用資料庫既有真實資料（滙豐旅人系列 3 張卡：無限卡／御璽卡／輕旅卡）驗證，發現**改成依卡片代號雜湊還不夠**——原本的雜湊函式在小調色盤（8色）＋相似字首（`hsbc-travelone-*`）下仍會撞色（3張中2張撞色）。改用 FNV-1a 雜湊函式＋調色盤 8→12 色後，3 張卡實測各自拿到不同底色，問題解決。**此修正（雜湊 key 改為卡片代號＋FNV-1a＋12色調色盤）尚未寫入正式程式碼，待本任務正式核准後一併實作。**
    2. 使用者一度提議改用「油畫濾鏡」風格（對真實卡面照片套用固定參數濾鏡後呈現）。AI 分析後指出：濾鏡只改變筆觸與色階，晶片位置、圖示構圖、Logo 區塊仍可辨識，本質仍是對官方素材的風格轉換（衍生版本），並未真正降低著作權/商標風險，也沒解決「風格一致」的顧慮（因為每張卡的原始照片構圖本來就不同）。使用者理解後**放棄此方向**。
    3. 使用者對 SVG 原型的視覺質感給出直接負評（「太醜了」）。AI 產出 v2 加強版：底色改雙色漸層＋光澤、新增金屬質感晶片圖示、頂級卡別裝飾線改為貼合卡片外緣的金色細邊框（取代原本的色塊裝飾線）、銀行首字縮小讓漸層有呼吸空間、整卡加柔和投影。**這版視覺已獲使用者認可，是目前選定的視覺方向。**
    4. 使用者一度考慮「直接去官網抓取信用卡卡面」，理由是「沒有商業利益」。AI 提醒：著作權侵權與是否商業獲利無關（保護的是公開重製/傳輸行為本身），商標的「使人誤以為有官方關聯」疑慮也不需要商業動機成立；本站 T24 目前拍板方向是「純導引不含聯盟行銷」，缺少銀行常見的異業合作/聯盟行銷關係（多數比較網站能放官方卡面圖，通常是靠這類合作關係取得授權素材，而非單純截圖）。使用者理解此風險後，仍希望以「能抓到官方授權素材就用、抓不到才 fallback 用 SVG」為優先順序，AI 執行一輪唯讀網路研究，查核目前資料庫 7 家銀行（sinopac／cathay／esun／hsbc／taishin／ubot／ctbc）官網是否有公開的媒體專區/素材下載管道——**結果：7 家銀行皆未找到可直接取用的官方素材授權管道**，且查到的銀行網站著作權聲明範例（如渣打銀行台灣）多為「未經書面同意不得重製」的標準條款。這代表若要走官方素材路線，等於要逐一銀行去信詢問授權（即原本方案 (c)），不是能立即批次執行的選項。
    5. **2026-07-29 使用者最終決定**：綜合上述研究結果與 SVG v2 加強版的視覺確認，**採用參數化 SVG 卡面樣板（v2 質感版）作為目前選定方向**，取代原本「委託簡化插畫／未來視情況洽詢銀行授權」的開放態度。若未來個別銀行主動同意提供官方素材，屬於另外的加值選項，非目前 Scope 的必要條件。

## 目標

訂出一套「卡面圖像呈現規則」，明確規定卡面圖片能不能直接使用銀行官方素材、如果不行要用什麼替代方案，讓後台 `imageUrl` 欄位與資料蒐集流程有清楚規範可循，避免著作權／商標風險，且不必每次要放圖片時都重新猶豫一次。
