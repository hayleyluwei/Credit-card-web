# T23 卡面圖像視覺風格規則

建立日期：2026-07-27（Asia/Taipei）
任務卡版本：v1（草案）
核准狀態：待核准
問題類型：架構設計／內容文件

> **狀態說明**：本任務卡只記錄規劃討論結果，**不構成任何實作授權**。在使用者核准 Scope 版本之前，不得繪製／收集任何卡面圖片、不得修改 `Card.imageUrl` 的既有使用邏輯。

## 背景

2026-07-27 使用者提出疑慮：之後要幫平台上的信用卡補上真實卡面圖片時，如果直接從銀行官網抓取卡面照片或去背圖直接使用，是否比較好改一下風格再呈現？

查證現況（2026-07-27）：資料庫目前 **11 張卡，0 張設有 `imageUrl`**，前台一律以卡片名稱首字的色塊頭像（`CardImage` 元件的 fallback）呈現，尚未實際使用過任何真實卡面圖片。因此這是一個**預防性**任務——趁還沒有人蒐集/上傳任何卡面圖片之前，先定規則，而不是問題已經發生。

這個顧慮的核心是：銀行卡面設計與行內 Logo 通常屬於銀行的商標／著作權資產，直接抓取官網圖片重製在第三方網站上，可能有著作權或商標權疑慮。這與本專案既有的內容政策一致——規格書已明文規定文字內容「KOL 文章只參考資訊架構與選題，不得抄錄原文，數字回官方來源查證後改寫」；卡面圖片若直接沿用官方素材，等於是同一類風險換了一種媒材。

相關文件：
- `src/components/CardImage.tsx`（現有卡面圖片元件，含無圖時的色塊頭像 fallback）
- `prisma/schema.prisma` 的 `Card.imageUrl`／`imageAlt` 欄位
- `docs/data-collection/DATA_COLLECTION_SPEC_信用卡優惠資料蒐集與分類規格書-v3-2026-07-27.md`（內容來源與著作權原則章節）

## 已確認決策

- 使用者 2026-07-27 傾向：**不直接沿用銀行官網的卡面照片**，希望之後如果要放卡面圖片，先經過風格轉換再呈現。
- **使用者 2026-07-27 選定方向 (b)：委託簡化插畫**（保留卡片配色與大致版型意象，不逐像素重製官方設計）。
- **待解決的執行方式問題（使用者 2026-07-27 提出）**：使用者擔心無論是 Claude 或 Codex，AI 圖像生成工具都無法保證多張卡片之間風格一致——這是真實存在的技術限制，AI 逐次生成的插畫在線條、配色飽和度、視角上本來就會有變異，不是能單純靠「講清楚一點」解決的問題。
- **AI 提出的替代執行方案（待使用者確認是否採用）**：與其請 AI「畫」每張卡的插畫（每次生成結果不可控），改用**參數化 SVG 樣板系統**——由工程端設計一份可重複使用的卡片視覺樣板（簡化幾何造型、依銀行/卡片等級決定主色、依發卡組織顯示對應簡易圖示等），每張卡的視覺由同一份樣板套入資料產生，而非個別生成的獨立創作。優點：風格保證一致（本質是同一段程式碼），新卡加入時自動套用不需要重新設計，且不重製官方卡面設計、著作權風險低。這改變了「委託插畫」的執行方式定義：從「請人／AI 逐張手繪」變成「設計一套規則、寫程式產生」。
  - **原型已完成（2026-07-27）**：AI 用 4 張真實卡片資料（`esun-unicard`／`hsbc-travelone-infinite`／`ctbc-line-pay-card`／`taishin-richart-card`，涵蓋乾淨值、英文 tier、複合雜亂字串、全 null 四種情況）產生參數化 SVG 卡面，發布為 Artifact 供使用者檢視。規則：底色依銀行 slug 雜湊固定指派（8 色深色盤）、發卡組織標籤從 `cardNetwork` 關鍵字比對抽取（抽不到不顯示原始字串）、金色 tier 裝飾線依 `cardLevel` 關鍵字比對顯示。**原型未觸及任何正式程式碼**（`CardImage.tsx` 未修改），純獨立展示頁。**待使用者回饋**：是否喜歡這個視覺方向、要不要調整，回饋後才會決定是否正式寫進核准 Scope。

## 目標

訂出一套「卡面圖像呈現規則」，明確規定卡面圖片能不能直接使用銀行官方素材、如果不行要用什麼替代方案，讓後台 `imageUrl` 欄位與資料蒐集流程有清楚規範可循，避免著作權／商標風險，且不必每次要放圖片時都重新猶豫一次。

## Scope v1（規劃內容；核准實作前不得執行）

若後續拍板通過，預期的實作範圍包含：

- 研究記錄信用卡卡面圖片的著作權／商標風險（銀行卡面設計、行內 Logo 使用限制的一般認知；不涉及法律諮詢）。
- 提出至少兩種可行的視覺呈現方案供使用者選擇，例如：
  - (a) 沿用並強化現有「色塊＋文字」風格系統（非寫實、不重製官方設計，零著作權風險，但辨識度較低）。
  - (b) 找設計師／使用素材庫繪製簡化的示意卡片圖（保留卡片配色與大致版型意象，但不逐像素重製官方設計）。
  - (c) 洽詢銀行是否提供官方素材使用授權（若有官方合作管道，風險最低但耗時，且不是所有銀行都有此管道）。
- 使用者選定方向後，制定卡面圖片的蒐集／製作流程，並更新 `DATA_COLLECTION_SPEC` 對應章節（新增「卡面圖片來源與呈現規則」小節）。
- 視選定方案，評估是否需要調整 `CardImage.tsx` 元件或 `Card.imageUrl` 欄位定義（例如改存「插畫版」圖片而非官方照片連結）。
- 建立 T23 Summary，更新任務索引與 CURRENT_STATE。
