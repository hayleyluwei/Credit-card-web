# T16 第一版正式資料匯入

建立日期：2026-07-08（Asia/Taipei）
任務卡版本：v1
核准狀態：已核准
問題類型：功能／內容文件

## 背景

資料整理人員依 `docs/data-collection/DATA_COLLECTION_SPEC_信用卡優惠資料蒐集與分類規格書-v1-2026-07-08.md` 與對應 Excel 模板整理真實信用卡優惠資料。網站目前資料庫內容是開發用測試 seed 資料（含虛構銀行與測試卡），第一版上線不得對外顯示。需要把整理好的試算表資料驗證後匯入本機資料庫，取代測試資料。

上層計畫：`docs/superpowers/plans/2026-07-08-FIRST_RELEASE_第一版上線實作計畫.md`

## 已確認決策

- 資料交付格式為四工作表試算表（banks / cards / offers / offer_cards），欄位定義以規格書 v1 為準。
- 回饋類型中文值對應系統代碼：現金回饋=cashback、點數回饋=points、折扣=discount、分期=installment、其他=other。
- 第一版資料庫**完全清除** seed 測試資料（使用者 2026-07-08 拍板）。
- 首頁既有未提交變更處理方式為 **commit**（使用者 2026-07-08 拍板）；T16 開始前執行，該次 commit 仍需執行當下的 Git 操作確認。

## 目標

整理好的試算表資料經過自動檢查後完整載入本機開發資料庫，網站前台顯示的銀行、卡片、優惠全部來自真實資料。

## Scope v1

- 建立 `scripts/import-offer-data.mjs` 匯入腳本，支援兩種模式：
  - `--dry-run`：只讀試算表並輸出檢查報告，不寫資料庫。
  - 正式匯入：檢查全數通過後寫入資料庫。
- 檢查項目（乾跑與正式匯入皆執行）：
  - 必填欄位不為空（依規格書第 5 節）。
  - 銀行代號、卡片代號、優惠代號在各表內唯一。
  - offer_cards 與 cards 引用的代號都存在。
  - 每筆優惠在 offer_cards 至少有一列對應。
  - 主分類代碼屬於六個合法值；回饋類型屬於五個合法值。
  - 日期格式為 YYYY-MM-DD，結束日期不早於開始日期。
  - 每筆優惠有來源網址與查證日期。
- 優惠代號（slug）空白時由腳本自動產生並記入報告。
- 匯入前自動備份 `prisma/dev.db` 為帶日期戳的備份檔。
- 依核准決策清除測試 seed 資料（或建立乾淨資料庫檔案後匯入）。
- 產出匯入驗證報告（各表筆數對照、自動產生的 slug 清單、警告事項），存於 `docs/implementation/summaries/`。
- 在 `package.json` 增加對應 npm script（如 `data:import`、`data:import:dry`）。
- 建立 T16 Summary。

## Non-scope

- 不修改 Prisma schema、不建立 migration。
- 不修改前台頁面、API 或後台功能。
- 不修正試算表內容錯誤：乾跑檢查發現的資料問題退回資料整理人員修正，腳本不得自行猜測補值（slug 自動產生除外）。
- 不接觸正式環境、不部署。
- 不執行 push。

## 安全限制

- 只寫入本機 SQLite 開發資料庫，匯入前必須先完成備份。
- 寫入前依 `AI_WORKFLOW_AI協作流程.md` 取得 `.ai-worktree-lock.json`。
- 不讀取或輸出 `.env` 秘密值。
- 試算表中的來源網址只做格式檢查，不需要腳本連網驗證。

- API：不涉及。

## 驗證方式與完成定義

- 自動驗證：
  - `node scripts/import-offer-data.mjs --dry-run` 報告零錯誤。
  - 正式匯入後各表筆數與試算表一致（報告內對照）。
  - lint 與 build 通過（指令分類依驗證政策，未核准前由使用者執行或核准分類）。
- 人工驗收：使用者抽點首頁、分類頁、任一優惠詳情頁，確認顯示的是真實資料且無測試資料殘留。
- 完成定義：匯入報告零錯誤、人工抽點通過、Summary 完成。
- 部署驗證：不適用。

## 資料保護與回復方式

- 接觸本機開發資料庫 `prisma/dev.db`。
- 匯入前建立備份檔；失敗或不接受時以備份檔還原即可回復。
- 備份檔不進 Git（確認 `.gitignore` 覆蓋）。
