# T24 信用卡申辦導引連結

建立日期：2026-07-27（Asia/Taipei）
任務卡版本：v1（草案）
核准狀態：待核准
問題類型：功能／產品

> **狀態說明**：本任務卡只記錄規劃討論結果，**不構成任何實作授權**。在使用者核准 Scope 版本之前，不得修改 `Card`／`Bank` model、不得申請任何銀行的聯盟行銷／推薦碼帳號、不得修改任何程式碼。

## 背景

2026-07-27 使用者提出：目前平台的卡片頁與優惠詳情頁只有「來源連結」（連到銀行官方活動頁／官網），沒有直接的「立即申辦」或「前往官網申辦這張卡」導引連結。查證現況：確實沒有這個功能，`Bank.websiteUrl`／`Offer.sourceUrl` 都是內容查證用途，非導向申辦頁。

同一次對話也討論到：如果之後申辦連結要接銀行的**聯盟行銷（affiliate）／推薦碼**機制（帶追蹤參數、賺取分潤），這在性質上跟「下廣告」一樣屬於**營利／商業使用**，會影響 T18 部署平台的選擇——Vercel Hobby 方案明確排除商業用途，用聯盟連結賺分潤比單純放廣告更明確是商業行為，需要納入同一個平台決策一併考慮（見 T18 任務卡「風險與待決問題」段落的 Vercel Hobby 限制討論）。

相關文件：

## 已確認決策

- 本任務目前沒有已拍板的產品決策，待使用者逐項確認下方「風險與待決問題」後才能核准 Scope。

## 目標

每張信用卡的卡片頁／優惠詳情頁能提供清楚的「立即申辦」或「前往官網申辦」連結，導引使用者完成辦卡；若使用者決定串接聯盟行銷機制，能支援對應的推薦碼／追蹤參數。

## Scope v1（規劃內容；核准實作前不得執行）

若後續拍板通過，預期的實作範圍包含：

- `Card` model 新增申辦連結欄位（例如 `applyUrl`，需精準指向線上申辦頁，非銀行官網首頁；建立對應 migration，依 schema 專門流程執行）。
- 前台卡片頁、優惠詳情頁「適用信用卡」區塊新增「立即申辦」按鈕，連到申辦連結（新分頁開啟，避免使用者離開本站）。
- 後台卡片表單新增對應欄位輸入與驗證（URL 格式檢查）。
- 資料蒐集規格書視需要新增「申辦連結」欄位規範與填寫方式。
- 若使用者決定要串接聯盟行銷：另外研究各銀行是否有官方聯盟行銷計畫、申請條件與流程（此為後續調查工作，需使用者自行申請帳號，AI 不代為申請）。
- 建立 T24 Summary，更新任務索引與 CURRENT_STATE。

## Non-scope

- **不現在申請任何銀行的聯盟行銷／推薦碼帳號**：帳號申請一律由使用者自己執行；是否要做聯盟行銷本身也是待決問題，不預設一定要做。
- 不保證能取得各銀行官方合作資格；部分銀行可能沒有公開的聯盟行銷計畫。
- 不修改任何優惠內容準確性規則、不影響既有「官方來源查證」機制。
- 不涉及金流、分潤結算或任何收款機制的技術實作。
- 不接觸正式環境、不部署、不執行 `git add`／commit／push。

## 風險與待決問題

- **待使用者決定：申辦連結是否要帶聯盟行銷／推薦碼機制，還是先做「純導引到官網申辦頁」的陽春版本。** 兩者影響大不同：純導引版本不構成明確的商業營利行為，跟 Vercel Hobby 條款衝突風險較低；聯盟行銷版本則明確是營利行為，可能需要提前把 T18 的部署平台決策（見「有其他平台下廣告可以更便宜嗎」的討論，Railway／Render 等平台無此限制）納入考慮。
- 若要做聯盟行銷，需要逐一調查各銀行是否有公開計畫、申請門檻與審核時間，可能不是所有卡片都能串上。
- 「立即申辦」連結若導去銀行申辦頁後使用者填寫個資，本站僅提供導引，不涉及任何個資蒐集或轉手，此界線需在頁面文案上清楚說明，避免使用者誤解本站有代辦性質。
- 本任務排程與 T18（上線）、T23（卡面視覺）等任務線的相對順序尚未討論，可視使用者優先順序決定。
