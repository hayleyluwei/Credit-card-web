# T17 上線前完整測試

建立日期：2026-07-08（Asia/Taipei）
任務卡版本：v1
核准狀態：已核准
任務狀態：完成（2026-07-27 使用者拍板接受自動驗證＋AI 示範測試＋16 筆資料抽查結果，當作完成往下走；後台登入編輯項由使用者自行補跑）
問題類型：驗收部署

## 背景

T16 完成後，本機資料庫已載入第一版真實信用卡優惠資料。上線前需要確認：網站功能在真實資料下全部正常、資料內容與官方來源一致、沒有測試資料殘留。既有 smoke 測試多依測試 seed 資料撰寫，換成真實資料後需重建。

上層計畫：`docs/superpowers/plans/2026-07-08-FIRST_RELEASE_第一版上線實作計畫.md`
依賴：T16 完成。

## 已確認決策

- 測試對象是載入真實資料的本機環境（dev server），不是正式環境。
- 人工測試由使用者（或使用者指定的人）依測試腳本執行，AI 不得代為認證人工測試通過。

## 目標

產出並執行一套涵蓋前台、後台、資料品質的上線前測試，全部通過後網站取得「可部署」狀態。

## Scope v1

- 建立「正式資料完整性檢查」腳本 `scripts/verify-release-data.mjs`（唯讀）：
  - 資料庫無測試銀行、測試卡、虛構優惠殘留。
  - 每筆已發布優惠有：標題、摘要、詳細說明、分類、至少一張對應卡、來源網址、查證日期。
  - 無已過期仍標示發布的優惠（或確認前台確實不顯示）。
  - 已發布優惠、卡片、銀行筆數輸出供對照。
- 更新或停用依測試 seed 撰寫、已不適用的既有 smoke 腳本（逐一列出處置方式，不得默默刪除）。
- 建立人工測試腳本 `docs/implementation/manual-test-scripts/T17-上線前測試腳本-v1-2026-07-08.md`，涵蓋：
  - 首頁：精選優惠、分類入口、卡片入口。
  - 六個分類頁：清單、分頁、排序。
  - 搜尋：至少三組真實關鍵字（銀行名、卡名、通路名）。
  - 優惠詳情頁：怎麼拿到優惠、回饋與限制、注意事項、適用信用卡、來源連結可點開。
  - 銀行頁與卡片頁。
  - 過期優惠不顯示於前台。
  - 後台：登入、編輯一筆優惠並確認前台反映。
  - 手機寬度檢視主要頁面。
  - SEO 基本項：主要頁面 title 與 description 非空、無亂碼。
- 建立資料抽查清單：隨機抽 10–20% 優惠（至少 10 筆），列出「優惠標題、來源網址、要核對的欄位」，由人工逐筆與官網比對回饋數字、期間、條件。
- 執行自動驗證並記錄結果；建立 T17 Summary。

## Non-scope

- 不修改產品功能與 UI（測試發現的 bug 另開任務卡或經使用者核准後擴充 Scope）。
- 不修改 Prisma schema 與資料內容（資料錯誤退回資料流程處理）。
- 不接觸正式環境、不部署、不執行 push。
- 不做效能壓測與資安滲透測試。

## 安全限制

- 驗證腳本一律唯讀，不得寫資料庫。
- lint、build、dev server 啟動等指令的分類依驗證政策；未列入核准白名單的指令需使用者核准分類或由使用者執行。
- 寫入檔案（腳本與文件）前取得 `.ai-worktree-lock.json`。

## 影響範圍

- 頁面與 route：只讀取檢視，不修改。
- API：不涉及。
- 資料模型與資料流：唯讀檢查。
- 共用元件：不涉及。
- 文件與測試：新增驗證腳本、人工測試腳本、抽查清單、Summary；調整不適用的舊 smoke。
- 外部服務：人工抽查需開啟銀行官網頁面（僅瀏覽）。

## 驗證方式與完成定義

- 自動驗證：`node scripts/verify-release-data.mjs` 通過；lint 與 build 通過。
- 人工驗收：使用者執行 T17 人工測試腳本全部通過；資料抽查無重大錯誤（回饋數字錯誤、來源連結失效、優惠已下架仍顯示，皆屬重大）。
- 完成定義：自動驗證通過 + 人工測試腳本通過 + 抽查完成且重大錯誤為零；三者證據記入 Summary 後，任務標記完成，網站狀態為「可部署」。
- 部署驗證：不適用（屬 T18）。

## 資料保護與回復方式

- 本任務不寫入資料庫，只讀取。
- 測試中發現資料錯誤時記錄清單，交由 T16 流程重新匯入修正，本任務不直接改資料。
