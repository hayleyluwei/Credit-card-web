# 第一版上線實作計畫

建立日期：2026-07-08（Asia/Taipei）
版本：v1（草稿，待使用者核准）
用途：把「整理好的信用卡優惠資料」放進網站、完成上線前測試、部署為第一版對外版本的整體規劃。本計畫拆成三張任務卡（T16、T17、T18），依序執行，**每張任務卡都需使用者個別核准後才能實作**。

## 整體目標

網站以「真實、可查證的信用卡優惠資料」取代目前的測試資料，通過上線前測試後，部署為第一版公開網站。

## 前置條件（開始 T16 前必須滿足）

1. 資料整理人員已依規格書交付試算表：
   - 規格書：`docs/data-collection/DATA_COLLECTION_SPEC_信用卡優惠資料蒐集與分類規格書-v1-2026-07-08.md`
   - 模板：`docs/data-collection/信用卡優惠資料整理模板-v1-2026-07-08.xlsx`
2. 交付的試算表已通過規格書第 6 節的自我檢查（來源齊全、代號唯一、對應完整）。
3. 首頁信用卡入口既有未提交變更的去留已由使用者決定（commit 或撤回），工作區乾淨。

## 三個階段

| 階段 | 任務卡 | 產出 | 依賴 |
|---|---|---|---|
| 1. 資料匯入 | T16 | 匯入腳本 + 本機資料庫載入正式資料 + 匯入驗證報告 | 試算表交付 |
| 2. 上線前測試 | T17 | 自動驗證通過 + 人工測試腳本執行完成 + 資料抽查報告 | T16 完成 |

- `docs/implementation/tasks/T16-FIRST_RELEASE_DATA_IMPORT_第一版正式資料匯入.md`
- `docs/implementation/tasks/T17-PRE_LAUNCH_TESTING_上線前完整測試.md`
- `docs/implementation/tasks/T18-FIRST_RELEASE_DEPLOYMENT_第一版部署上線.md`

## 階段一：T16 正式資料匯入（摘要）

- 建立匯入腳本：讀取試算表四個工作表（banks / cards / offers / offer_cards），先跑「乾跑檢查」產出錯誤報告（缺必填、代號重複、對應不到、分類代碼不合法、日期格式錯誤），全部通過才寫入本機資料庫。
- 匯入前備份現有 `prisma/dev.db`。
- 匯入後正式資料取代測試 seed 資料；第一版網站不得出現測試銀行、測試卡或虛構優惠。
- 產出匯入驗證報告：各表筆數與試算表一致、抽樣比對欄位內容。

## 階段二：T17 上線前完整測試（摘要）

- 自動驗證：lint、build、既有 smoke 中適用者（需使用者核准分類後執行）、新的「正式資料完整性檢查」。
- 人工測試腳本（新版）：首頁、六個分類頁、搜尋、優惠詳情頁、銀行頁、卡片頁、過期優惠不顯示、後台登入與編輯、手機版檢視、SEO 基本項（title/description）。
- 資料抽查：隨機抽 10–20% 優惠，逐筆點開「來源網址」核對回饋數字、期間、條件是否與官網一致。
- 完成定義：自動驗證全過 + 人工測試腳本全過 + 抽查無重大錯誤（數字錯、來源失效視為重大）。

## 階段三：T18 第一版部署上線（摘要）

- 依 Roadmap 傾向方案（尚未核准，T18 核准時一併拍板）：網頁 Vercel Hobby、資料庫 Neon Free（PostgreSQL）。
- SQLite → PostgreSQL 遷移：schema provider 調整、migration、把 T16 匯入的正式資料轉入 Neon。
- 環境變數與後台管理帳號在正式環境的設定（不得把密碼寫進文件或 log）。
- 上線後驗證：正式網址首頁、分類頁、搜尋、優惠詳情逐項檢查；確認後台可登入。
- 已知限制：Vercel Hobby 禁止商業用途，未來加入分潤或廣告前需升級或改平台（Roadmap 已記錄）。
